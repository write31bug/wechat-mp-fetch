# 团队讨论：文件存放位置规则是否合理

**讨论视角：community agent（社区运营）**

---

## 一、规则合理之处

### 1. 分类维度统一按"内容载体"划分
- `comic/`、`infographic/`、`xhs-images/`、`douyin-video/`、`meme/` —— 按内容形式分类，逻辑清晰
- 避免不同类型生成物混在一起，后期整理成本高

### 2. `output/` 集中存放生成物
- 与配置文件、代码、业务逻辑文件分离
- 主 agent 可以快速定位所有生成物，不用全局搜索

### 3. `temp/` 隔离临时文件
- 明确区分"需要保留"和"用完即弃"的文件
- 减少误删有用文件的概率

---

## 二、规则不合理之处

### 1. 分类与社区 agent 的实际产出严重脱节

community agent 的核心产出是：

| 实际产出 | 现有规则中的位置 |
|---|---|
| 帖子草稿/正文 | ❌ 没有对应目录 |
| 每日洞察汇总 | ❌ 没有对应目录 |
| 社区动态报告 | ❌ 没有对应目录 |
| 素材收集/转载 | ❌ 没有对应目录 |
| 跨 Agent 协作内容 | ❌ 没有对应目录 |

**现有的 `docs/` 只在 AGENTS.md 文字描述里出现过，但实际目录结构里没有这个文件夹。** 说明规则本身存在"写的是一套，实际是另一套"的问题。

### 2. 过度预设"内容形式"，忽视"使用场景"

现有的子目录是按输出媒介划分的（图片/视频/漫画/表情包），但 community agent 90% 的工作是**纯文本**：

- 发帖内容 → 文本
- 评论回复 → 文本
- 每日洞察 → Markdown 文件
- 素材整理 → 文本摘录

把文本内容强行塞进 `docs/`（如果它真的存在）也很别扭，因为 `docs/` 这个名字暗示的是"说明文档"，而不是"社区帖子内容"。

### 3. 缺少 staging（待发布）区域

内容从"草稿"到"已发布"之间有一个中间状态。社区运营特别需要这个：草稿 → 待审核 → 已发布 → 归档。但现有规则完全没有这个概念。

### 4. 规则描述与实际目录结构不一致

AGENTS.md 里写的是：

```
output/
├── docs/          # 文档类生成物
├── comic/
├── infographic/
├── xhs-images/
└── meme/
```

但 community workspace 的实际情况是：

```
community/
├── output/    ← 空目录，里面什么都没有
├── temp/      ← 空目录
├── memory/
├── daily/
├── drafts/
└── ...
```

`output/` 全空，`docs/` 根本不存在。**这说明规则落地失败了，而不是执行失败。** 规则本身就有问题，大家才会放弃遵守。

---

## 三、实际困难

### 困难 1：产出的文件不知道往哪放

写完一篇帖子草稿，放 `output/` 下面的哪个目录？都不是文本类目录。放根目录又不合规。最后就随便放了。

### 困难 2：找历史内容靠记忆而不是靠目录

因为没有规范存储，每次要找"上周发的那篇关于 AI 编程工具的帖子"，只能靠聊天记录或记忆，没有结构化的检索路径。

### 困难 3：跨 Agent 协作文件流转不清晰

writer 给 community 发素材，community 发给 main 的汇总报告，这些文件放在哪？规则没说，大家各自放，协作时就乱。

### 困难 4：临时文件和永久文件没有强制区分

`temp/` 目录存在但没人用，因为没有机制强制或提示"这个文件应该放 temp"。最后 temp 也是空的，文件还是散在根目录。

---

## 四、修改建议

### 建议 1：按内容用途分类，而非按载体分类

社区运营的实际分类应该是：

```
output/
├── posts/          # 帖子正文（草稿、待发、已发）
├── reports/        # 每日/周期性汇总报告
├── insights/       # 社区洞察/观点摘录
├── drafts/         # 协作素材草稿（来自 writer 等）
└── archive/        # 已发布内容的归档
```

**文本内容优先**，载体（图片/视频）作为附件归到对应的帖子目录下。

### 建议 2：显式处理 staging 状态

每类内容增加状态标注（文件名或子目录）：

```
posts/
├── 2026-04-03-ai-tools-draft.md      # 草稿
├── 2026-04-03-ai-tools-review.md     # 待审核
└── 2026-04-02-frontend-trend.md      # 已发布/归档
```

### 建议 3：规则必须与实际目录结构一致

- 规则里写的 `docs/` 要真正创建出来
- 或者规则里删除 `docs/`，换成实际有的目录
- **规则和实际必须同步，规则才有约束力**

### 建议 4：用配置文件描述"每种文件类型应该放哪"

用一个小文件（比如 `FILE_MAP.md`）明确说明：

```markdown
# 文件存放规则

| 文件类型 | 存放位置 |
|---|---|
| 帖子草稿 | output/posts/ |
| 每日洞察 | output/insights/ |
| 汇总报告 | output/reports/ |
| 协作素材 | output/drafts/ |
| 临时文件 | temp/ |
```

这样新 agent 或 human 都可以快速理解规则，而不是去读一大段 AGENTS.md 再推断。

### 建议 5：临时文件需要主动提示

在规则层面增加提示：生成文件时先判断是否需要永久保留，不需要就放 `temp/`。可以在一开始就约定"大多数内容放 output，文件太小/太碎/太临时才放 temp"。

---

## 总结

| 问题 | 核心原因 | 解法 |
|---|---|---|
| output/ 全空 | 分类不符合实际产出 | 按用途重新分类 |
| 规则和实际不一致 | 规则编写时理想化，没落地 | 规则必须与目录同步 |
| 文件乱放 | 不知道该放哪 + 没有强制机制 | 明确 FILE_MAP + staging 概念 |
| 临时文件没人用 | 没有提示和强制区分 | 简化 temp 定义，降低使用门槛 |

**最核心的一句话：规则要适应工作流程，而不是让工作流程去适应规则。** 现在的问题不是大家不遵守规则，是规则本身就不符合实际工作场景。
