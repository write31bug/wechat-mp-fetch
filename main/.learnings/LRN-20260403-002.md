# LRN-20260403-002 · 技术 · subagent session 清理

## 触发场景

执行 subagent session 清理任务时，发现 OpenClaw CLI 的 `openclaw sessions delete` 命令不存在（error: too many arguments for 'sessions'. Expected 0 arguments but got 2）。一开始尝试用 `sessions delete <key>` 格式，失败后改成各种参数组合，都失败。最后查 help 发现 `sessions` 子命令只有 `cleanup`，根本没有 `delete`。

## 根因

OpenClaw 的 session 删除功能尚未在 CLI 层实现（虽然 API 可能存在）。sessions CLI 的设计是不接受 key 作为参数的。

## 正确做法

直接操作 session store 文件：
1. 调 `openclaw sessions --all-agents --json` 获取 session 列表（含 key/ageMs/agentId）
2. 解析各 agent 的 `sessions.json`（位于 `~/.openclaw/agents/{agentId}/sessions/sessions.json`），删除对应 key 条目
3. 将对应的 `.jsonl` 文件重命名为 `.jsonl.deleted.{时间戳}`

## 筛选 session 的可靠字段

CLI 返回的数据里，以下字段**不可用**：
- `status`：CLI 不返回这个字段
- `abortedLastRun`：CLI 中该字段意义不同，不能区分活跃/结束
- `systemSent`：只表示 gateway 是否尝试向该 session 推过消息，subagent 一般不触发

可用字段：
- `key` 含 `:subagent:` → 识别是 subagent session
- `ageMs` → 识别超时时长
- `agentId` → 定位 sessions.json 位置

## 验证结果

- 清理前：132 个 subagent session（123 个超过 2h）
- 清理后：9 个（全部 < 2h）
- cron 已配置，每小时自动执行

## 教训

CLI 命令不存在就承认，不要循环尝试参数组合。先查 `--help` 再执行。
