### 3. Subagent Session 清理问题（已完成 ✅）

**问题**：subagent 跑完后 session 不自动删除，堆积在 gateway 里

**根因定位**：
- `cleanup=keep`（默认）时：archiveAtMs=undefined，sweeper 跳过，session 永不删除
- `cleanup=delete` 时：registry entry 立即删除，但 .jsonl 文件本身不删（设计问题）
- `openclaw sessions delete` CLI 命令不存在（API 未实现）
- 60分钟 auto-archive 是理论值，实际不生效

**最终方案**：直接操作 sessions.json + 重命名 .jsonl 文件

**筛选条件**：
- `key` 含 `:subagent:`
- `ageMs > 2小时`
- **不依赖 status/abortedLastRun/systemSent**（CLI 数据里这些字段无法区分活跃/结束）

**脚本路径**：`E:\openclaw\main\scripts\cleanup_subagent_sessions.py`
- 调 CLI 获取 session 列表
- 从各 agent 的 sessions.json 中移除对应条目
- 将 .jsonl 文件重命名为 `.jsonl.deleted.时间戳`

**清理结果**（2026-04-03 11:24）：
- 清理前：132 个 subagent session（123 个超过 2h）
- 清理后：**9 个**（全部 < 2h，均为活跃 session）

**cron 定时任务**（已配置）：
- 任务名：`cleanup-old-subagent-sessions`
- cron 表达式：`0 * * * *`（每整点，Asia/Shanghai）
- 运行模式：isolated session，delivery=none（静默）
- jobId：`8f97a124-38aa-459a-9243-998a85890b27`
- 下次执行：12:00，之后每小时一次

**注意**：CLI 的 `openclaw sessions delete` 命令不存在，不要再试
