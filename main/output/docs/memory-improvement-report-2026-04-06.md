# 小金记忆力改善方案 — 团队讨论报告

**日期：** 2026-04-06
**参与：** 💻 dev · ✍️ writer · 📊 finance · 🌐 community · 🤖 小金
**议题：** 如何改善小金的长期记忆能力

---

## 一、问题本质

经过三轮集体讨论，团队共识是：

> **小金的记忆问题是"易失性"而非"容量性"。** 每次 session 重置后记忆清零，不是脑子不够用，是什么都没留下来。

核心矛盾：
- **断裂**：跨会话上下文消失（技术调试/持仓判断/系列文章）
- **混乱**：矛盾结论无法追溯，判断前提失效仍在被引用
- **遗忘**：风格偏好/用户关系/素材引用每次从零

---

## 二、外部调研（Round 0）

四个视角各调研了 2-3 条外部最佳实践：

| 视角 | 经验 |
|------|------|
| 💻 dev | 分层记忆架构（working/short-term/long-term）；语义/情景/程序三类分类存储；会话末摘要写入 |
| ✍️ writer | 渐进式摘要（原文→加粗→缩写→一句话）；PARA分类（按行动组织而非主题）；AI辅助检索联想 |
| 📊 finance | 信息标签化打标；记忆分层（工作 vs 长期）；RAG统一知识库 |
| 🌐 community | 减少重复解释是用户最大痛点；分层记忆（身份层+状态层+历史层）；跨时间察觉规律 |

## 三、四视角诊断（Round 1）

### 💻 dev — 技术实现
1. **跨会话上下文断裂** — 调试到一半 session 重置，上下文全丢
2. **技术决策历史无法追溯** — 方案/结论散落，被推翻又重新讨论
3. **Skill 配置状态黑箱** — API key/模型/状态不透明，调用常踩坑

### ✍️ writer — 内容表达
1. **风格记忆丢失** — 不知道金哥调性偏好，指令没说就保守输出
2. **系列文章上下文断裂** — 第1篇结论完全不记得，每篇独立成篇
3. **素材用完即弃** — 数据引用下次找不到，只能重新搜

### 📊 finance — 投研风控
1. **持仓决策链断裂** — 建仓逻辑/加减仓触发/核心矛盾每次从零解释
2. **矛盾结论无法追溯** — 1月超配/3月低配，依据变化未被记录
3. **判断前提丢失** — 利率环境逆转后判断仍被自信引用

### 🌐 community — 用户视角
1. **对话断层** — 用户每次从头解释背景，重复劳动
2. **用户关系碎片化** — 历史交互全部丢失，当新用户处理
3. **热点话题无前世今生** — 同一话题反复出现但不积累结论

## 四、交叉回应（Round 2）

### 💡 关键共识

- **dev 的核心判断**：三个架构缺陷 — 数据无结构（扁平文本丢 metadata）· 实体无建模（User/Portfolio/Topic 非对象）· 知识无版本（结论无时间戳）
- **finance 的冷面立场**：很多"记忆问题"本质是**显式化不足**，应强制文档化，而非依赖隐式记忆
- **writer 的洞察**：判断前提失效却仍在引用 = "幽灵引用"，是最危险的一种错误
- **community 的定性**：记忆是"易失性"非"持久性"，解决方向是让记忆变成资产

---

## 五、落地优先级方案

### 🥇 第一优先 — 今天就能动（零技术依赖）

#### ① 「金哥写作偏好档案」— writer 提出
- **动作：** 在 MEMORY.md 新建一个写作偏好章节
- **内容：** 目标读者、调性偏好、结构习惯、禁止词、系列规则
- **效果：** 每次写作任务直接读档案，不用重复说
- **状态：** 待金哥填内容

#### ② 「一句话用户档案」— community 提出
- **动作：** 社区互动超过3轮后，在 memory/ 文件里写一行用户印象
- **格式：** 用户名 + 关心领域 + 立场偏好 + 值得记住的点
- **效果：** 用户再来时主动暖场，"上次你提到..."
- **状态：** 社区运营自用

#### ③ 「Session末技术快照」— dev 提出
- **动作：** 每次实质性会话结束前，LLM 生成 tech-snapshot.md
- **内容：** 未完成任务（含卡点/已试方案/下一步）+ 进行中决策 + 最近完成 + Skill 状态
- **效果：** 新 session 启动时自动加载，"接着上次继续"
- **状态：** 需更新 AGENTS.md 规则

---

### 🥈 第二优先 — 需要一点结构化

#### ④ 「决策即落盘」— finance 提出
- **动作：** 会话中涉及买卖/评级/宏观判断时，强制写入 decision-log.md
- **格式：** 标的 + 结论 + 置信度 + 有效期 + 前提条件 + 待验证风险
- **效果：** 持仓讨论可接力，新会话先查历史结论，矛盾时主动弹窗
- **状态：** 待 finance 小弟配置

#### ⑤ 「判断前提标签」— writer 提出
- **动作：** 每条重要结论附加≤3个前提标签
- **效果：** 引用前核验前提是否仍有效，避免幽灵引用
- **状态：** 设计阶段

---

### 🥉 第三优先 — 中长期架构

- **结构化持仓对象**（dev）：JSON+schema 替代扁平字符串
- **用户统一数据模型**（dev）：user_id → profile.json + interaction_log.json
- **话题知识库版本化**（writer）：topic_id + 结论 + 置信度 + 前提 + 更新时间
- **矛盾检测提示**（finance）：新决策前主动提示方向相反的历史结论
