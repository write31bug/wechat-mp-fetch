# OpenClaw 记忆持久化问题 — 团队讨论总结

**讨论日期：** 2026-04-06  
**参与团队：** dev / writer / finance / community（全员）  
**讨论轮次：** R0调研 → R1自诊 → R2交叉回应 → R3收敛

---

## 一、核心诊断结论（四组共识）

**记忆断裂的本质不是"记不住"，而是"没有在正确的时间把信息写下来"。**

四组提出的痛点看似不同，根因都是同一个：**session 结束时信息跟着消失，下一个 session 从零开始。**

---

## 二、各组痛点自诊

### 💻 dev 视角

| 痛点 | 描述 |
|------|------|
| **跨会话技术上下文断裂** | 调试到一半 session 重置，上下文全丢，下次还要从零描述 |
| **技术决策历史无法追溯** | 之前讨论过的方案/结论散落各处，可能被推翻又重新提起 |
| **Skill 配置状态黑箱** | 各 skill 的 API key、模型、当前状态不清楚，调用容易踩坑 |

### ✍️ writer 视角

| 痛点 | 描述 |
|------|------|
| **风格记忆丢失** | 每次新会话都不知道金哥调性偏好，指令没说就只能保守输出 |
| **系列文章上下文断裂** | 写到第3篇时第1篇的框架和结论完全不记得 |
| **素材用完即弃** | 查过的数据/引用下次完全找不到，只能重新搜 |

### 📊 finance 视角

| 痛点 | 描述 |
|------|------|
| **持仓决策链断裂** | 持仓历史（建仓逻辑、加减仓触发因素）全部消失，每次从零解释 |
| **矛盾结论无处追溯** | 1月超配、3月低配，两次结论的依据变化没有被显性记录 |
| **市场判断前提丢失** | 旧判断在利率/政策环境变化后仍被引用，前提已失效 |

### 🌐 community 视角

| 痛点 | 描述 |
|------|------|
| **对话断层** | 用户聊完离开再回来完全从头开始，每次都要重复解释背景 |
| **用户关系碎片化** | 每个用户都当新用户处理，历史交互/偏好/贡献全部丢失 |
| **热点话题无前世今生** | 同一话题反复出现但不积累之前的讨论结论和分歧 |

---

## 三、交叉洞察（R2 各组互相回应）

- **finance + writer 共鸣：** 记忆的本质不是存原始对话，而是**提炼档案**——决策叙事链、读者档案、风格规范，本质都是提炼过的结构化沉淀
- **dev + community 共鸣：** 扁平文本丢失 metadata（时效性、来源、状态），导致信息无法被正确使用
- **finance + community 共鸣：** 结论没有时间戳和前提链，变成"有依据的地雷"——最危险的错误
- **dev 的架构警告：** User / Portfolio / Topic 不是独立对象，数据无结构、实体无建模、知识无版本

## 四、各组收敛方案（R3）

### 💻 dev —「Session 末技术快照」

**核心思路：** 在 session 结束前自动生成技术快照，写入 `memory/tech-snapshot.md`，下次启动时自动加载。

**快照格式：**
- 🔴 未完成任务（卡点 / 已试方案 / 下一步 / 来源 session）
- 🟡 进行中决策（选项 / 当前倾向 / 待确认 / 来源 session）
- 🟢 最近完成
- 📡 Skill 状态速记

**触发条件：** 超过 10 轮交互 或 有未完成技术任务

---

### ✍️ writer —「金哥写作偏好档案」

**核心思路：** 在 MEMORY.md 中建立一份长期写作风格档案，每次写作任务结束后追加更新。

**档案字段：** 目标读者 / 文章调性 / 结构偏好 / 内容偏好 / 系列规则 / 禁止词

**特点：** 今天就能初始化，不需要技术开发，解决最高频痛点（每次任务都要重新解释调性）

---

### 📊 finance —「决策即落盘」规则

**核心思路：** 每次涉及具体标的买卖决策/评级调整/宏观判断，强制生成结构化快照写入 `finance/data/decision-log.md`。

**快照格式：**
- 结论（买入/卖出/持有 + 理由）
- 置信度（高/中/低）
- 有效期（季报后/宏观拐点/止损触发）
- 前提条件
- 待验证风险

**进阶：** 矛盾检测——做新决策前检索同标的的历史结论，若方向矛盾主动提示

---

### 🌐 community —「一句话用户档案」

**核心思路：** 每次社区互动超过 3 轮，在 `memory/YYYY-MM-DD.md` 追加结构化用户印象。

**格式：**
```
[用户印象] {用户名}
- 关心领域：{一句话}
- 立场/偏好：{一句话}
- 值得记住的点：{一句话}
```

**效果：** 下次见到同一用户，开场说一句暖场（"上次你提到想了解 RAG 应用，找到一个案例了"）
