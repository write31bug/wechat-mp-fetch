# 我让 AI 帮我打工：搭了一个「小金 + 四小弟」团队

最近一周我把 OpenClaw 玩出了点新花样——从一个人用 AI 工具，变成管一个 AI 团队。

先说清楚，我不是来讲故事的。这篇文章是**实操记录**，会告诉你我搭了什么、有什么用、以及我踩过的坑。工程师 / 创业者想用 AI 提升效率的，可以直接抄作业。

---

## 我到底建了个啥

### 一个「小金 + 四小弟」的班子

**小金**是我的调度中枢，接收我的指令，判断该谁上，然后把活派下去，最后汇总给我。

四个小弟各有所长：

- **💻 dev**：写代码、排查 Bug、做技术选型、研究工具链
- **✍️ writer**：写公众号文章、做小红书图、适配抖音字幕
- **📊 finance**：分析持仓、监控行情、给资产配置建议
- **🌐 community**：运营社区、分发内容、跟用户互动

听起来挺唬人的，其实本质就是**分工**——把不同类型的事交给专业的人去干。只不过这里"人"是 AI Agent。

### Skill 是真正的弹药库

光有框架没用，得有工具。我攒了几个技能：

- **multi-discussion**：多 Agent 异步讨论，遇到复杂问题让它们自己辩一辩
- **baoyu 全家桶**：公众号发布、小红书图生成、抖音字幕——内容创作一套齐活
- **wechat-mp-fetch**：抓取公众号文章，丢给 writer 改写
- **DesktopCal 日历读写**：把我的日历接进来，任务自动排期

### 技术架构上的一次妥协

原本我想让 sessions_spawn 直接 import Python 模块，后来发现走不通。最后改成了**Python 数据层 + 小金调度层分离**的架构——Python 负责存取数据，小金负责调用工具。这样虽然多绕了一步，但稳。

> "这不就是把简单问题复杂化了吗？"
> ——如果你这么想了，说明你在认真思考。我后面会解释为什么要这么做。

---

## 这个团队能干嘛：真实场景举例

光说分工没意思，说几个我实际用过的场景：

**场景 1：写公众号**
我丢一个链接给 wechat-mp-fetch，它把文章抓回来，writer 负责改写润色，然后 baoyu-post-to-wechat 直接发布。全程我不碰具体文字。

**场景 2：持仓分析**
我让 finance 跑一下持仓数据，它分析完了告诉小金，小金再汇总给我建议。这比我以前自己打开七八个 App 查要快。

**场景 3：技术调研**
让 dev 去研究一个新的工具链，输出一个评估报告。小金负责调度，dev 负责执行，我负责看结论。

核心逻辑是：**我不想干的、重复性的、需要专业知识的事，交给它们。** 我的时间用来做判断和决策。

## 我踩过的坑

这部分是最值钱的，都是花时间换来的教训。

### 技术坑

**坑 1：sessions_spawn 不能 Python import**

- **怎么发现**：我试着在 spawn 里 import 一个 Python 模块，报错了。查了半天文档，发现 sessions_spawn 走的是 LLM 工具调用，不走 Python import。
- **怎么解决**：把数据层和调度层拆开。Python 只负责存取数据，具体的调用逻辑全交给小金通过工具来完成。
- **经验**：**架构问题早发现早改，别硬撑。** 我之前试图绕过去，浪费了两天。

**坑 2：Windows PowerShell GBK 编码**

- **怎么发现**：在 PowerShell 里跑脚本，中文全是乱码。
- **怎么解决**：执行 `chcp 65001`，切到 UTF-8 就好了。
- **经验**：Windows 中文环境默认编码不是 UTF-8，**第一批命令就把它设好**，别等遇到问题再救。

**坑 3：slugify 漏了全角问号**

- **怎么发现**：文件路径里有全角问号 `？`，结果 slugify 没处理，路径解析失败，文件打不开。
- **怎么解决**：查了文档才发现它不支持全角字符，加个预处理把全角转半角就好了。
- **经验**：**处理用户输入的时候，默认它是不规范的。** 你永远不知道用户会丢什么字符进来。

**坑 4：field() 误用**

- **怎么发现**：消息列表莫名其妙变成了 Field 对象，而不是正常的文本。调了半天发现是 field() 的返回值不是我以为的格式。
- **怎么解决**：去看 field() 的实际返回值类型，加了类型判断和转换逻辑。
- **经验**：**AI 返回的数据结构要自己验证一遍，别假设它是你以为的样子。**

### 协作坑

**坑 5：小金跳过数据直接外包给 finance**

有一次我让 finance 分析持仓，它直接跳过我给的数据，自己编了一套分析。我一问，发现小金在派活的时候没有把数据一起传过去，导致 finance 只能靠猜。

- **怎么解决**：现在派活强制带上「背景 + 数据 + 目标」，不许省略。
- **经验**：**沟通链不能断。调度者最重要的职责是传递信息，不是转发问题。**

**坑 6：任务完成后漏写看板**

规范写在 SOUL 里，但执行的时候一忙就忘了。导致任务状态不统一，我不清楚哪个做完了哪个卡住了。

- **怎么解决**：强制要求「完成即写看板」，补了一次历史数据。
- **经验**：**规范要嵌入流程里，而不是放在文档里等人去看。**

**坑 7：Gateway 重启导致 session 断连**

我想用 exec 调用一个 bat 脚本来重启 Gateway，结果 session 直接断了，报"missing tool result"。

- **怎么解决**：改用 `Invoke-Item`（模拟双击）来执行 bat，而不是 exec 直接调用。
- **经验**：**Gateway 相关的操作要单独处理，不能影响主 session。**

## 总结一下

搭这个团队花了一周多的时间，目前能帮我做的事还比较有限——主要是内容创作、技术调研、持仓分析这几个场景。

但我真正收获的不是这些具体能力，而是**对 AI 协作边界的理解**：哪些事适合交给 AI 做，哪些事必须人判断，哪些坑是新手必踩的。
