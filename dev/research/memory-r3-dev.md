# Round3 收敛 — dev 改进方案

**作者：** dev  
**日期：** 2026-04-06  
**背景：** 结合 Round1 诊断（未完成任务断裂、技术决策无追溯、skill 配置黑箱）和 Round2 交叉洞察（扁平存储缺 metadata、结论缺前提链、实体无建模），提一个最优先落地改进

---

## 改进名称

**Session 末技术快照（Tech Snapshot）自动化**

---

## 针对哪个痛点

**最痛的点：** 每次新 session 启动，小金不知道自己"是谁"，不知道自己"在干什么"，不知道"有什么悬而未决"。

Round1 诊断了三个问题：跨会话技术上下文断裂、技术债务无追溯、skill 配置黑箱——三者有一个共同根因：**session 结束时什么都没留下，下一个 session 什么都接不上。**

Round2 进一步揭示：扁平存储丢 metadata（时效性、来源、状态），导致即使留下了信息，也很难被正确使用。

**核心断裂点：** session 结束的那一瞬间。信息在这里清零。

---

## 具体怎么改（步骤）

### 第一步：在 session 结束前注入"快照触发"

在 AGENTS.md 的"每日记忆规范"之后，增加一条规则：

> 每次实质性会话结束时（超过 10 轮交互 或 有未完成的技术任务），由 LLM 主动生成一份**技术快照**，写入 `memory/tech-snapshot.md`。

触发条件由 LLM 自己判断，不需要用户说"帮我存一下"。

### 第二步：快照模板（固定结构，解决 metadata 缺失）

快照文件格式如下：

```markdown
# Tech Snapshot - {date}

## 🔴 未完成任务
- [task_id] {任务描述}
  - 卡点：{具体是什么卡住了}
  - 已试方案：{方案1（失败原因）/ 方案2（失败原因）}
  - 下一步：{下一步计划}
  - 来源 session：{YYYY-MM-DD}

## 🟡 进行中决策
- {决策问题}
  - 已有选项：{A / B / C}
  - 当前倾向：{X，理由是...}
  - 待确认：{还需要什么信息}
  - 来源 session：{YYYY-MM-DD}

## 🟢 最近完成（供下次快速恢复上下文）
- {任务} - 已解决 {解决方案简述}

## 📡 Skill 状态速记
- {skill名}：{上次调用结果}（{日期}）
- {skill名}：{上次调用结果}（{日期}）
```

这个模板解决了 Round2 揭示的"扁平存储缺 metadata"问题：每个条目都带**来源 session 日期**，LLM 知道"这条信息是什么时候产生的"。

### 第三步：启动时自动加载

在 AGENTS.md 的"Session Startup"流程中，增加一步：

> 4. 读取 `memory/tech-snapshot.md`，若存在则在开场白中提及："【上下文恢复】你上次的未完成任务：..."

这一步由 main agent 自己在启动时执行，不需要额外的自动化脚本。

---

## 预期效果

**直接效果：**
- 新 session 启动时，小金能主动说"上次你让我调 baoyu-imagine 的 API，报错是 401，我计划下一步换 key 重试"
- 同样的问题不再需要金哥重复描述两遍

**连锁效果：**
- 未完成任务的快照是结构化的（任务/卡点/已试/下一步），自然为后续的决策追溯（ADR）和 skill 状态追踪打好数据基础
- 来源 session 日期解决了"信息是否还新鲜"的问题，是后续时效性检查的最小前提

**不做的风险（为什么这个排第一）：**
- 排在"建立技术决策日志"和"skill 状态清单"之前，因为它是**唯一一个今天就能启动、明天就能看到效果**的动作
- 其他两个改进都需要额外的存储 schema 设计，这个改进只需要改 prompt 规则 + 一个固定模板

---

## 实施成本

- **时间：** < 1 小时（写模板 + 修改 AGENTS.md）
- **依赖：** 无外部依赖，纯规则变更
- **风险：** 低——只是多了一次 LLM 生成动作，不影响现有功能
