**研究目标**：港大 OpenSpace AI Agent 自我进化引擎 → OpenClaw 接入可行性分析

## 一、OpenSpace 核心技术解析

### 1.1 是什么

OpenSpace 是香港大学数据智能实验室（HKUDS）开源的**自我进化 Skill 引擎**，通过 MCP 协议接入任意 AI Agent（OpenClaw / nanobot / Claude Code / Cursor 等），赋予其从真实任务中自动学习、修复和共享 Skill 的能力。

**核心数据**：
- Token 消耗减少 **46%**
- 收入（任务价值）提升 **4.2 倍**（vs 同等骨干 LLM 的 ClawWork 基线）
- 50 项专业任务测试：合规 +18.5%、工程 +8.7%、文档 -56% Token

### 1.3 三大自我进化模式

| 模式 | 触发条件 | 效果 |
|------|---------|------|
| **FIX** | Skill 执行失败或工具退化 | 就地修复，更新 SKILL.md |
| **DERIVED** | 从成功 Skill 衍生专用版 | 创建新 Skill 目录，保留父子关系 |
| **CAPTURED** | 从成功执行中提取新模式 | 全新 Skill，无父级，完全自创 |

### 1.4 三大触发器

1. **Post-Execution Analysis**：每次任务后分析，推荐进化方向
2. **Tool Degradation Detection**：工具成功率下降时，自动找到所有依赖 Skill 批量进化
3. **Metric Monitor**：定期扫描 Skill 健康指标（应用率 / 完成率 / 回退率），进化表现不佳者

### 1.5 关键洞察

> **最有价值的 Skill 不是领域知识，而是「工具可靠性和错误恢复」**  
> GDPVal 测试中，165 个进化出的 Skill 里：  
> - 文件格式 I/O：44 个（PDF 解析回退、DOCX 等）  
> - 执行恢复：29 个（分层回退策略）  
> - 文档生成：26 个  
> - 质量保障：23 个（写后验证）  

**本质**：OpenSpace 让 Agent 学会「如何在不完美的真实世界环境中可靠交付」。

## 二、OpenSpace vs OpenClaw 现有能力对比

### 2.1 能力对照表

| 能力维度 | OpenSpace | OpenClaw 现有能力 | 重叠度 |
|---------|-----------|-----------------|--------|
| **Skill 生命周期管理** | 自动捕获 / 修复 / 进化 / 共享 | 静态 SKILL.md（只读） | ❌ 无重叠 |
| **Skill 检索（RAG）** | BM25 + Embedding + LLM 混合排序 | skill-creator 搜索插件 | ⚠️ 部分 |
| **质量追踪** | 工具级 / Skill 级 / 代码执行级三层监控 | ❌ 无 | ❌ 无重叠 |
| **多 Agent 协作** | 云端 Skill 共享 + 群体智能 | ❌ 无 | ❌ 无重叠 |
| **自我修复** | FIX 模式：分析根因 → Diff 修复 → 验证上线 | self-improvement：被动记录错误 | ⚠️ 弱重叠 |
| **任务执行引擎** | Grounding Agent（内置 MCP 工具层） | ✅ 内置 exec / read / write 等核心工具 | ⚠️ 部分 |
| **Browser 自动化** | MCP 后端（GUI backend = Anthropic Computer Use） | agent-browser skill（独立 CLI） | ⚠️ 部分 |
| **流程编排** | ❌ 无（纯任务执行） | clawflow：flow 状态机 + 子任务调度 | ⚠️ 部分 |
| **增量 Diff 更新** | ✅ 基于 Diff 的最小化 Skill 更新 | ❌ 无（skill-creator 是全量创建） | ❌ 无重叠 |
| **版本 DAG（谱系追踪）** | ✅ 每个 Skill 版本存储完整 lineage | ❌ 无 | ❌ 无重叠 |
| **安全防护（反 Prompt Injection）** | ✅ 内置检查 | ❌ 无专门防护 | ❌ 无重叠 |
| **云端 Skill 社区** | ✅ open-space.cloud | ❌ 无 | ❌ 无重叠 |

### 2.2 关键差异总结

**OpenClaw 的强项（OpenSpace 没有的）**：
- 多 Agent 流程编排（clawflow 状态机）
- 主动式任务调度（cron / heartbeat）
- Skill 创作工作流（skill-creator）
- 浏览器自动化（agent-browser）
- 插件系统和 MCP Server 扩展

**OpenSpace 的强项（OpenClaw 没有的）**：
- 自动化 Skill 进化（FIX/DERIVED/CAPTURED）
- 质量监控（三层追踪 + 级联进化）
- 跨 Agent 群体智能（云端社区）
- 真实任务驱动的错误恢复模式学习
- 增量 Diff 更新（而非全量重写）
- 版本谱系追踪（SQLite DAG）

## 三、接入方案

### 3.1 接入路径

OpenSpace 提供**路径 A**（作为 MCP Server 接入 Agent），而 OpenClaw 已支持 mcporter（OpenClaw 的 MCP 运行时）。官方文档明确说明：

```
openclaw uses mcporter as its MCP runtime.
mcporter config add openspace --command "openspace-mcp" \
 --env OPENSPACE_HOST_SKILL_DIRS=/path/to/openclaw/skills \
 --env OPENSPACE_WORKSPACE=/path/to/OpenSpace \
 --env OPENSPACE_API_KEY=sk-xxx
```

**推荐方案：不改核心代码，通过 mcporter 注册 OpenSpace MCP Server。**

### 3.2 关键接入步骤

**Step 1：安装 OpenSpace**
```bash
git clone --filter=blob:none --sparse https://github.com/HKUDS/OpenSpace.git
cd OpenSpace
git sparse-checkout set '/*' '!assets/'
pip install -e .
openspace-mcp --help  # 验证安装
```

**Step 2：复制两个 Host Skills 到 OpenClaw**
```bash
cp -r OpenSpace/openspace/host_skills/delegate-task/  <openclaw>/skills/
cp -r OpenSpace/openspace/host_skills/skill-discovery/ <openclaw>/skills/
```

**Step 3：通过 mcporter 注册 MCP Server**
```bash
mcporter config add openspace --command "openspace-mcp" \
 --env OPENSPACE_HOST_SKILL_DIRS=<openclaw>/skills \
 --env OPENSPACE_WORKSPACE=/path/to/OpenSpace \
 --env OPENSPACE_API_KEY=sk-xxx   # 可选，云端功能
```

**Step 4：配置 OPENSPACE_WORKSPACE 指向 OpenSpace 仓库路径**

### 3.3 依赖清单

| 依赖 | 类型 | 说明 |
|------|------|------|
| Python 3.10+ | 强制 | OpenSpace 基于 Python |
| pip install -e . | 强制 | OpenSpace 安装 |
| mcporter | 强制 | OpenClaw 已内置 |
| Git | 强制 | Clone OpenSpace |
| openspace-mcp 命令 | 强制 | MCP Server 入口 |
| OPENSPACE_API_KEY | 可选 | 云端社区（可先跳过） |

### 3.4 接入后的能力扩展

接入后 OpenClaw 将获得 4 个 MCP Tools：
- `execute_task`：多步任务执行（内置 Skill 检索 + 自动进化）
- `search_skills`：本地 + 云端 Skill 搜索
- `fix_skill`：手动修复损坏的 Skill
- `upload_skill`：上传进化后的 Skill 到云端社区

同时两个 Host Skill 会自动教导 OpenClaw **何时**调用这些工具。

## 四、优先级与价值评估

### 4.1 值得接入吗？

**结论：值得，但优先级中等。**

| 评估维度 | 评分 | 理由 |
|---------|------|------|
|  Token 节省 | ⭐⭐⭐⭐⭐ | 实测 46% Token 减少，直接省钱 |
| 能力增强 | ⭐⭐⭐⭐ | 补足 OpenClaw 最缺的自我进化闭环 |
| 接入难度 | ⭐⭐⭐ | mcporter 已内置，官方有文档 |
| 维护成本 | ⭐⭐⭐ | Python 依赖，OpenSpace 活跃开发中 |
| 社区价值 | ⭐⭐⭐⭐ | 云端 Skill 共享有网络效应 |
| 安全性 | ⭐⭐ | Skill 自动执行 + 云端下载需谨慎评估 |

### 4.2 优先级建议

**P1（立即做）**：接入基础路径 A，获得 execute_task + search_skills
- 成本极低（mcporter 已是现成）
- 收益明确（Token 节省 + 任务成功率提升）
- 适合：金哥自己用，感受进化效果

**P2（值得做）**：将进化出的高质量 Skill 反哺 OpenClaw 社区
- OpenSpace 的 Skill 上传不需要改 OpenClaw 核心
- 可以把 OpenClaw 专用 Skill 上传到 open-space.cloud

**P3（未来探索）**：
- 研究 OpenSpace 的 Quality Monitor 机制，看能否借鉴到 OpenClaw skill-creator
- 探索 OpenSpace 的 grounding agent loop 能否与 clawflow 联动

### 4.3 风险提示

1. **安全**：Skill 自动修复涉及写入文件，存在 Prompt Injection 风险——OpenSpace 有内置防护，但需评估
2. **Python 依赖**：OpenClaw 是 Node.js，引入 Python 服务增加复杂度
3. **维护负担**：OpenSpace 活跃开发中，API 可能变化
4. **云端社区**：上传 Skill 需 API Key，涉及数据出境考量

---

## 五、结论一句话

OpenSpace 是 OpenClaw **最值得补充的外部能力**：Token 节省效果有硬数据支撑，接入路径官方原生支持（mcporter），不改核心代码即可获得自我进化闭环。主要风险是 Python 依赖和云端安全考量——建议先用本地模式（P1）验证效果，再决定是否深度集成。
