# 工作区文件存放规则讨论

**讨论人：** dev agent  
**日期：** 2026-04-03

---

## 一、规则分析

### 合理的部分

1. **`output/` 和 `temp/` 分离**  
   核心价值明确：生成物永久保留，临时文件定期清理。这个分类逻辑本身没问题。

2. **子目录按产物类型划分**  
   `comic/`、`infographic/`、`xhs-images/`、`douyin-video/`、`meme/` 这几个品类在 baoyu-skills 实际业务中是独立的生产线，分开存放有助于后续检索。

3. **`memory/` 和 `skills/` 独立**  
   记忆和技能定义不混入生成物流程，职责清晰。

---

### 不合理的部分

1. **`docs/` 缺失**  
   当前 `output/` 只有媒体类子目录，但实际工作会大量产出文档类产物（方案、讨论记录、汇报）。这类文件要么乱塞到根目录，要么塞进某个媒体子目录，非常违和。

2. **按"发布平台"分目录，而非"内容类型"**  
   `xhs-images/` 和 `douyin-video/` 是按平台分的，但 `comic/` 和 `meme/` 又是按内容类型分的。逻辑不一致——同一个内容可能既发小红书又发抖音，按平台分就会造成文件重复或版本混乱。

3. **`temp/` 边界模糊**  
   "临时"没有明确定义：AI 生成的多轮草稿算不算临时？调试输出的中间文件算不算？没有约束力，最终还是乱放。

4. **没有规定"过程文件"放哪**  
   实际工作中存在大量介于临时和永久之间的文件：草稿、中间版本、待审核版。这些在规则里找不到归宿，一般就堆在根目录或塞进某个 output 子目录。

5. **`*.md` 散落根目录**  
   AGENTS.md、SOUL.md、IDENTITY.md、TOOLS.md、USER.md 全挤在根目录。如果业务扩张，配置文件增加，根目录会越来越臃肿。

---

## 二、实际困难

1. **文档无处可去** → 最终散落在各 Agent 的工作区根目录，污染根目录
2. **多平台复用同一素材** → 同一个图要发抖音又要发小红书，按平台分目录就要复制或移动，版本容易不一致
3. **临时文件实际没清理** → 因为没明确什么是临时、谁负责清理、什么时候清理，`temp/` 形同虚设
4. **没有统一的命名规范** → 文件名乱起，搜索靠猜

---

## 三、修改建议

### 方案：精简分类 + 明确边界

```
workspace/
├── output/           # 生成物（永久保留）
│   ├── docs/          # 文档（新增）
│   ├── media/         # 媒体文件（合并 comic/infographic/meme/xhs-images/douyin-video）
│   │   └── 命名规范：{内容描述}_{版本}_{日期}
│   └── archives/      # 归档（不常用但不能删的）
├── temp/             # 临时文件
│   └── .gitkeep       # 标记目录存在，提醒会清理
├── memory/           # 每日记忆
├── skills/           # 技能定义
└── config/           # 配置文件（新增，*.md 归入）
```

**核心改动：**

1. **媒体类合并** — 不再按平台分，而是按内容类型（都是媒体文件）。如果需要区分平台，用文件名标签而非目录。
2. **增加 `docs/`** — 文字类产物必须有归宿。
3. **增加 `config/`** — 集中管理 *.md 配置文件，根目录清爽。
4. **temp/ 加 .gitkeep + 规则说明** — 明确临时文件范围和清理机制。
5. **命名规范** — 推荐 `{类型}_{描述}_{版本|date}` 格式，不强制但给出指引。

---

## 四、结论

现有规则方向对，但分类维度和边界定义不清晰，导致执行成本高、结果混乱。核心问题是：**规则没有覆盖所有产物类型，所以实际工作者要么自创规则，要么直接乱放**。

建议优先解决 `docs/` 归宿问题和 `temp/` 的约束力，这两点改动最小、收益最大。
