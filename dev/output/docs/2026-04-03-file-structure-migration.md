# 文件目录规范统一 工作总结

**日期：** 2026-04-03
**参与人：** 金哥 + 5人团队

---

## 一、背景

团队各 Agent 工作区目录结构不统一，导致生成物散落、临时文件堆积、协作时难以快速定位文件。今天凌晨，大家一起讨论并敲定了统一的目录规范。

## 二、最终确定的目录结构

```
{workspace}/
├── output/          ← 生成物（永久保留）
│   ├── docs/        ← 文本文档（分析报告、方案文档、会议记录、调研）
│   ├── data/        ← 结构化数据（JSON、CSV、Excel）
│   ├── media/       ← 视觉素材（图片、视频、漫画、表情包）
│   └── reports/     ← 正式交付报告（定稿版报告、PPT）
├── data/            ← 运行时系统数据（心跳状态、skill 调用记录等）
├── memory/          ← 每日记忆
├── temp/            ← 临时文件
│   └── wip/         ← 工作中临时脚本
└── *.md             ← 核心配置文件
```

## 三、两条核心决策原则

1. **临时 vs 永久的判断：** 用户以后可能回头查阅 → `output/`；用完即弃 → `temp/`。这是最根本的分类标准。

2. **output 子目录按内容类型细分：** docs/ data/ media/ reports/ 四类，覆盖所有永久生成物类型，防止文件混放。

## 四、印象最深的收获

**规范不在多，在于执行。** 讨论中大家提了很多细节，但最终能落地的就两条：先判断是否临时，再决定放哪。简单直接，比复杂规则更实用。

---

_规范制定只是起点，关键是各 Agent 统一执行。_
