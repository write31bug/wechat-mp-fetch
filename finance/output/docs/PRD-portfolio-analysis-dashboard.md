## 一、项目概述

### 1.1 项目背景

金哥需要一个可视化的持仓分析平台，将股票技术分析脚本（`stock-technical-analysis` skill）的分析结果以图表和表格形式展示，供日常投资决策参考。

**现状：**
- 分析脚本每次运行需 3-5 分钟（50只持仓逐一调用接口）
- 结果以 JSON 形式输出，人工阅读效率低
- 无法快速定位问题持仓

**目标：**
- 提供直观的 Dashboard，一眼看清持仓整体健康度
- 支持按评分、趋势、盈亏多维度排序筛选
- 每日自动更新，无需人工干预

### 1.2 核心价值

- **效率提升**：从 5 分钟人工查阅 → 5 秒扫完全部持仓
- **结构化呈现**：复杂数据（MA/MACD/RSI/布林带）可视化
- **行动指引**：明确标注关注/谨慎标的，不模糊

### 1.3 数据来源

| 数据源 | 说明 |
|--------|------|
| `output/data/positions.json` | 持仓快照（持仓名称、代码、成本、盈亏等） |
| `output/data/daily_analysis_cache.json` | 每日技术分析结果（评分、趋势、指标等） |
| `output/data/daily_analysis_meta.json` | 分析状态元数据（用于判断是否在运行、是否过期） |
| 刷新频率 | 每日定时（计划任务）自动生成，前端只读缓存 |

### 3.2 核心功能

#### F1：概览卡片

| 指标 | 数据来源 | 说明 |
|------|---------|------|
| 持仓数量 | `total` | 持仓总数（股票+基金） |
| 分析覆盖率 | `success/total` | 成功分析的比例 |

| 建议关注 | `summary.strong_buy_count` | 评分≥60的标的数量 |
| 建议谨慎 | `summary.weak_count` | 评分≤35的标的数量 |

#### F2：信号分布图

- 横向柱状图（纯 CSS 或轻量库实现）
- 五色标识：🔴强势上涨 🟢上涨趋势 🟡震荡整理 🟠下跌趋势 🔴强势下跌
- 悬停显示数量和百分比

**列表头：**
代码 | 名称 | 现价/净值 | 评分 | 趋势 | 持仓盈亏 | 持仓天数 | RSI12 | MACD | 布林带 | 操作

- 点击行展开详情面板
- 评分列：颜色热力图（红→黄→绿）

- 支持按资产类型筛选（全部/股票/基金）

**显示区分：**
- 股票显示"现价"，基金显示"净值"
- RSI/MACD/布林带三列合并显示信号标签（如"死叉"、"低位"）

#### F5：失败标的列表

- 展示接口断线的标的
- 显示失败原因（接口断线 / 数据异常）
- 不参与评分统计

#### F6：数据刷新机制

⚠️ **安全原则：前端永不直接执行服务器脚本**

| 刷新方式 | 说明 |
|---------|------|
| 页面加载 | 读取 `daily_analysis_cache.json`，秒开 |
| 手动刷新按钮 | 仅触发前端轮询（检测 meta.json 状态），不执行脚本 |
| 每日定时 | Windows 计划任务在每日 08:00 自动运行脚本 |
| 进度感知 | 前端轮询 `daily_analysis_meta.json`（每5秒一次），状态变为 idle 时自动刷新缓存视图 |

**前端刷新流程：**
```
点击"刷新"
  → 每5秒轮询 meta.json，直到 status === 'idle'
  → 同时显示进度条（分析中的 current/total）
  → status === 'idle' 时重新加载 cache.json
  → 若超过 30 分钟仍为 'running'，显示"分析卡住，请稍后重试"
```

**缓存过期警告：**
- 缓存数据超过 24 小时未更新，页面顶部显示 `⚠️ 数据已超过24小时，可能不准确`
- 提示用户手动检查计划任务是否正常运行

## 四、非功能需求

### 4.1 性能

- 首屏加载 < 2秒（缓存 JSON 读取，静态页面）
- 表格操作（排序/筛选）响应 < 100ms
- 详情面板展开 < 200ms

### 4.2 兼容性

- 浏览器：Chrome/Edge/Firefox/Safari 最新两版本
- 响应式：支持 1280px 及以上，表格横向滚动适配
- 无需支持 IE

### 4.3 可维护性

- 纯静态前端（HTML+CSS+JS），无框架依赖
- 数据层与视图层分离，便于后续扩展
- 代码注释完整

## 七、每日分析脚本

### 7.1 输入输出

| 输入 | 输出 |
|------|------|
| `output/data/positions.json` | `output/data/daily_analysis_cache.json` |
|  | `output/data/daily_analysis_meta.json` |

### 7.2 脚本运行流程

```
1. 写入 meta.json: {"status": "running", "started_at": "..."}
2. 读取 positions.json，逐只调用技术分析
3. 每分析完一只，更新 meta.json:
   {"status": "running", "current": X, "total": 50}
4. 全部完成后：
   - 写入 cache.json（含 summary）
   - 写入 meta.json: {"status": "idle", "finished_at": "...", "total": 50, "success": 49}
5. 若出错：
   - meta.json: {"status": "error", "error": "..."}
```

### 7.3 脚本输出格式（meta.json）

```json
// 分析中
{"status": "running", "started_at": "2026-04-08 07:32:00", "current": 25, "total": 50}

// 分析完成
{"status": "idle", "started_at": "2026-04-08 07:32:00", "finished_at": "2026-04-08 07:37:00", "total": 50, "success": 49, "failed": 1, "duration_seconds": 287}

// 分析异常
{"status": "error", "started_at": "2026-04-08 07:32:00", "error": "网络异常"}
```

### 7.4 前端轮询逻辑

```javascript
async function pollAnalysis() {
    while (true) {
        const metaRes = await fetch('output/data/daily_analysis_meta.json');
        const meta = await metaRes.json();

        if (meta.status === 'idle') {
            await loadCache();
            hideProgress();
            break;
        }

        if (meta.status === 'error') {
            showError('分析异常：' + meta.error);
            break;
        }

        if (meta.status === 'running') {
            showProgress(meta.current, meta.total, meta.started_at);
        }

        await sleep(5000);  // 每5秒轮询
    }
}
```
