# 团队讨论：文件存放位置规则是否合理

**讨论角色：** finance 财务助手  
**日期：** 2026-04-03

---

## 一、这套规则哪些地方合理？

1. **分类清晰，有明确语义**  
   `output/` 下按内容类型分子目录（comic/、infographic/、xhs-images/ 等），逻辑上是通行的媒体管理思路，任何人看到都能快速理解"文件去哪儿找"。

2. **临时文件隔离**  
   `temp/` 独立出来是对的——临时文件和正式交付物混在一起会造成污染，清理时容易误删正式文件。

3. **永久 vs 临意的区分意识**  
   规则本身体现了"生成物需要归档、临时文件需要清理"的思路，这是好的设计意图。

---

## 二、这套规则哪些地方不合理？

### 1. 最大的问题：与 finance 的实际工作完全不匹配

finance 是**数据分析师**，不是内容创作者。

finance 的主要产出是：
- 股票/基金分析报告（Markdown/HTML）
- 数据表格（CSV、Excel）
- 行情截图
- 投资逻辑文档

这些内容**没有一种是 comic/infographic/xhs-images/ 的范畴**。把分析报告扔进 `output/docs/` 勉强能凑合，但没有"数据报告"这一类，而这是 finance 最核心的产出。

**结果：** 规则设计了 6 种媒体分类，全部用不上。finance 实际产出的东西无处可归，只能乱放。

### 2. "每次会话自动清理 temp/" 执行了，但永久文件没人管

`temp/` 清了，但 `output/` 全空——说明所有人都把正式文件也随手丢在别处了（根目录、桌面、临时文件夹）。**规则没有强制性，违规没有任何代价。**

### 3. memory/ 和 skills/ 的定位不清晰

- `memory/` 是每日记忆，但如果 finance 每次分析都生成中间数据，这些数据算"记忆"还是"生成物"？
- `skills/` 是技能定义，finance 自己定义的辅助脚本应该放哪？规则没说。

### 4. 没有处理"分析中间产物"的位置

一次完整的股票分析会经历：
1. 抓取原始行情数据 → 中间文件
2. 处理后的数据表 → 中间文件
3. 最终分析报告 → 最终产出

规则只有"最终生成物放 output/"，中间产物放哪？没有定义。**结果：要么污染根目录，要么随手放 temp/ 然后被清掉。**

---

## 三、实际工作中遇到的困难

1. **分析报告不知道往哪放**  
   写完一份股票分析，Markdown 文件随手留在根目录。下次找的时候一堆旧文件堆在一起，分不清哪个是最新版。

2. **数据文件被误清**  
   有时候把 CSV 数据文件放 `temp/` 做过渡，结果下次会话发现被清了，只能重新拉数据。

3. **output/docs/ 没有版本管理**  
   同一天分析了两遍茅台，第二份覆盖了第一份，没有历史版本。

4. **多人协作时文件散落**  
   如果其他 Agent 也在用这个 workspace，文件命名和存放位置没有约定，互相覆盖或找不到文件。

---

## 四、我建议怎么改

### 核心原则：**规则要适配工作类型，而不是让工作适配规则**

### 方案 A：按工作类型扩展 output/ 子目录（最小改动）

```text
workspace/
├── output/
│   ├── docs/           # 文档、分析报告（finance 最常用）
│   ├── data/           # 数据文件（CSV/Excel）
│   ├── charts/         # 图表、截图
│   ├── comic/          # 漫画（如有）
│   ├── infographic/    # 信息图（如有）
│   ├── xhs-images/     # 小红书图片（如有）
│   ├── media/          # 通用媒体
│   └── meme/           # 表情包
├── temp/               # 临时文件（会话级）
├── memory/             # 每日记忆
├── scripts/            # 辅助脚本（finance 自己用）
└── *.md                # 核心配置
```

**关键改动：** 新增 `data/` 和 `charts/`，这是 finance 高频产出但当前规则完全没有覆盖的类型。

### 方案 B：按工作流阶段分类（更精细）

```text
workspace/
├── raw/                # 原始数据（行情拉取后原始文件）
├── processed/          # 处理后数据
├── reports/            # 最终分析报告
├── assets/             # 图表、截图等附件
└── temp/               # 临时文件
```

**优点：** 天然区分中间产物 vs 最终产出，不会混淆。  
**缺点：** 对其他人（内容创作型 Agent）来说过于数据导向，不直观。

---

## 我的立场

**推荐方案 A**（最小改动，兼容现有），同时增加两条强制规则：

1. **所有正式文件必须进 output/ 对应子目录**，不留根目录。根目录只放配置（*.md）和文件夹结构本身。
2. **中间产物要有归宿**：如果一份数据是分析的基础资料，进 `data/`；如果只是单次会话的临时计算结果，进 `temp/`。规则要明确说清楚两者的区别，让执行者有据可依。

---

**结论：** 现有规则的"媒体分类"思路没问题，但不适用于所有 Agent 类型。finance 的核心产出是**文字报告 + 数据文件**，这两类在当前规则里都没有合适的家。补上 `data/` 和 `charts/`，规则就能真正用起来。
