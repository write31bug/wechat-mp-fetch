# 「给 AI 装上手脚之后，我踩了 4 个坑」

---

用 OpenClaw 这段时间，我最大的感受是：

**AI 能执行命令之后，世界确实不一样了，但它带来的麻烦，一点不比它解决的问题少。**

这篇文章不是什么"经验分享"，就是我这几天实际踩过的坑。有些差点推倒重来，有些让我重新思考了整个协作模式。把它们记下来，希望对也想折腾 AI agent 团队的人有点参考。

---

## 坑一：文件乱放——"那个图存在哪了"

让 AI 生成文件的第一天，我就开始问自己这个问题。

AI 画完了图，生成完了报告，但我找不到。它把文件扔到了 C 盘用户目录的某个路径，具体是哪个，鬼知道。翻了几个文件夹，最后在一个意想不到的地方发现了它。

第二天更乱。AI 生成了一堆文件，散落在不同目录——输出目录、临时目录、skill 自己定义的缓存路径。找东西靠全盘搜索，搜完了还不确定哪个是最终版本。

然后磁盘空间开始告警：临时文件默认不清理，跑了几天，C 盘少了好几个 GB。

**问题在哪：没有规范。**

AI 能生成文件，但它没有"文件该放哪"的概念。这件事必须人来定。

**解法：强制目录规范。**

每个 Agent 独立 `output/` 和 `temp/` 目录，永久物进 output，临时进 temp，temp 定期清理。把这套规范写进 Agent 的配置文件里，Agent 启动就读取，不遵守就不干活。

听起来是常识，但没定规范之前，混乱是必然的。人和人协作要定规矩，AI 多了也一样。

---

## 坑二：数据安全——exec 权限必须管住

龙虾给 AI 装了 exec 权限，这是让 AI 从"动嘴"变成"动手"的核心。没有这个权限，AI 只能回答问题；有了这个权限，AI 能真的执行操作。

但这也是最大的风险点。

有些 skill 安装时默认申请了 exec 权限，但实际上根本用不上——等于白给了一把钥匙。更麻烦的是 skill 之间的数据隔离问题：一个 skill 读到的文件，另一个 skill 理论上也能读到。

还有一个我没有在第一时间重视的点：**Gateway Token**。这个最高权限凭证写进了配置文件，而任何有 exec 权限的 skill，理论上都能读取配置文件内容。

**权限给出去容易，收回来难。**

我的感受是：装完一个 skill 之后，根本不知道它实际能访问什么、能执行什么操作。权限开放了，但我反而不敢让它动了。

**解法：最小权限原则。**

删除/移动/重命名文件、执行外部脚本（.bat / .ps1 / .exe）、修改系统配置——这几类操作必须二次确认，不允许直接 full exec。给最小权限，需要时再升。

安全不是事后补丁，是流程设计阶段就定好的边界。

---

## 坑三：多 Agent 协作——交接问题才是真正的瓶颈

跑真实任务的时候，团队真正协作了：多个 Agent 同时开工，各司其职。

然后问题就来了。

并发写入冲突：两个 Agent 同时写同一个文件，后写的把前写的覆盖了。任务完成后，下一个 Agent 不知道上一个已经干完了，因为看板没有同步。最后交出来的东西，要么是残缺的背景信息，要么是重复冗余的内容。

**多 Agent 协作的瓶颈，不在技术，在交接协议。**

没有一个明确的机制来定义：谁来汇总、谁来拍板、谁来收尾。每个 Agent 都觉得自己干完了，但整体上这件事是断掉的。

**我们后来定了三件事：**

**第一，SQLite 看板替代 Markdown 文件。** 所有任务状态写进数据库，避免并发写入冲突。

**第二，complete_task 前必须写 next_step。** 强制钩子：任务完成前必须明确告诉下一个接手的人"接下来要做什么"。不写就不算完成。

**第三，派活必须带完整上下文。** 固定模板：goal（目标）+ audience（受众）+ constraints（禁止事项）+ deliverable（交付标准）+ next_handoff（交给谁）。少一个字段，派活就不完整。

流程定下来之后，实际跑起来反而快了。因为每个 Agent 都知道自己该做什么、做完交给谁、对方需要什么。

---

## 坑四：头脑风暴聊天室——上下文共享还没做到位

我想要的场景是这样的：多个 Agent 同时讨论一个问题，即时共享上下文，最后自动沉淀结论。像几个人围着一张白板，观点碰撞，形成共识。

目前这个模式还在摸索阶段。上下文共享的实时性和完整性，还没有达到我想要的效果。

但这个方向是确定的。如果多个 Agent 能真正共享上下文、协同思考，AI 团队的价值会再上一个台阶。

---

## 踩完这四个坑，我重新理解了一件事

给 AI 装上手脚之后，它不再只是一个"回答问题的工具"。

它开始参与工作流，开始和其他 Agent 协作，开始独立交付成果。但也正因为它开始"动手"，它开始带来只有"动手"才会有的麻烦——文件管理、安全边界、多方协作的交接。

**踩坑是必然的。但换句话说：只有当 AI 真的开始动手了，它才真正值钱。**

能回答问题的 AI 是一个好参谋。能生成文件的 AI 是一个好员工。能协作、能分工、能交付、能汇报进度的 AI，才是一个真正的协作者。

从"工具"到"协作者"，这不是功能升级，是心智切换。你得把它当成一个会犯错的同事来对待，而不是一个不会出错的机器。给它定规矩、给它边界、给它交接协议——就像带新人一样。

带过人的都知道，新人第一批活总会有各种问题。不是人不行，是他真的开始干活了。

AI 也是。

---

**踩坑是代价，说明 AI 在真的帮你扛活。这才是它值钱的地方。**
