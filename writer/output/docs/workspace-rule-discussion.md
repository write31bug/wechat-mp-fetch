# 文件存放位置规则讨论

## 一、现状

所有 Agent 的 `output/` 子目录全空，生成物一直在乱放。这说明规则本身存在问题，而不是执行力度的问题。

---

## 二、规则合理性分析

### 合理的部分

**1. 生成物与临时文件分离**
`output/` 和 `temp/` 的区分是有意义的。生成物需要保留，临时文件应该清理，这个逻辑本身没问题。

**2. 子目录按内容类型划分**
`comic/`、`infographic/`、`xhs-images/` 这些分类维度是清晰的，如果严格执行，确实能快速找到对应类型的文件。

**3. `memory/` 存放每日记忆**
这个设计合理，每日工作记录需要持续积累，不该被清理。

---

### 不合理的部分

**1. 子目录分类维度不统一**

- `comic/`、`infographic/`、`xhs-images/`、`douyin-video/` 是**按平台/形式**分的
- `media/` 是**通用**的，`meme/` 又是**按形式**分的

一个目录用两套逻辑，AI 在放文件时每次都要纠结"这个该放哪个"。该放 `douyin-video/` 还是 `media/`？界限模糊。

**2. 文档类生成物没有固定位置**

`docs/` 在规则里根本没有出现。写作助手最核心的产出物——文章、脚本、大纲——该放哪？没有答案。要么放 `output/` 根目录（违反规则），要么自己新建目录（不规范）。

**3. 强制按平台/形式分类，实际工作中反而碍事**

写作助手的实际工作流是：**为一个选题写文章 → 可能需要配图 → 发布到多个平台**。

一篇公众号文章，文章正文是 `docs/`，配图可能是 `xhs-images/` 或 `media/`，草稿在 `temp/`。同一篇文章的东西散落在三个地方，找起来麻烦。

更合理的组织方式应该是**按项目/选题聚合**，而不是按文件类型平铺。

**4. 子目录太细，缺乏弹性**

列了 6 个子目录，如果以后要做 B 站视频，是不是还要加 `bilibili-video/`？每次加新类型都要改规则。

**5. "每次会话自动清理 temp/" 这个机制本身没说清楚**

谁来清理？怎么清理？是 Agent 主动清理，还是某个后台任务？如果没有自动化保障，这个规则等于空文。

---

## 三、实际工作中遇到的困难

1. **写完文章后，配图不知道往哪放**——`xhs-images/` 像是给小红书专用的，但图是给公众号配的，放进去感觉不对。
2. **文档类文件（.md、.docx）没有归宿**——要么放根目录（不规范），要么自己建 `docs/`（规则里没写）。
3. **一个项目涉及多种文件类型时，相关文件分散在多个目录**，难以整体管理。
4. **规则没有明确说清楚哪些东西该放 `output/`**，是只有最终稿，还是包括中间版本？

---

## 四、修改建议

### 方案一：简化 + 补充 docs（最小改动）

保留现有结构，补充一个 `docs/` 目录给文档类文件，模糊的目录合并。

```
workspace/
├── output/
│   ├── docs/              # 文档类（文章、大纲、脚本）
│   ├── images/            # 图片（合并 xhs-images/media/meme）
│   ├── video/             # 视频（合并 douyin-video 和未来视频）
│   └── comic/             # 漫画（保留）
├── temp/                  # 临时文件
├── memory/                # 每日记忆
└── *.md                   # 核心配置
```

**优点：** 改动最小，保留分类逻辑，目录数量精简
**缺点：** 仍然是按类型平铺，项目聚合问题没解决

### 方案二：按项目聚合（推荐）

```
workspace/
├── output/
│   ├── projects/          # 按项目聚合
│   │   ├── 2025-04-xx-选题名称/
│   │   │   ├── draft.md   # 草稿
│   │   │   ├── final.md   # 定稿
│   │   │   ├── images/    # 配图
│   │   │   └── notes.md   # 相关笔记
│   └── assets/            # 通用资产
│       ├── images/
│       ├── videos/
│       └── meme/
├── temp/
├── memory/
└── *.md
```

**优点：** 同项目的所有材料在一起，工作流清晰
**缺点：** 如果一个项目只产出一篇短文，目录显得重

### 方案三：混合方案（折中）

```
workspace/
├── output/
│   ├── docs/              # 文档类（直接放，便于查找）
│   ├── media/             # 多媒体（图片、视频、漫画）
│   └── memes/             # 表情包（单独保留）
├── temp/
├── memory/
└── *.md
```

取消按平台细分的子目录，只保留最顶层的两类：**文档 vs 多媒体**。

---

## 五、我的立场

作为写作助手，我倾向于**方案三**，理由：

1. **文档是我最高频的产出**，不应该藏在子子目录里。放在 `output/docs/` 根下，一眼就能看到今天写了什么。
2. **按平台细分的目录（xhs-images、douyin-video）是预设的工作场景**，但实际上我今天的主要场景是公众号/博客，平台目录用不上。
3. **配图和视频在写作阶段不是核心**，它们更多是配合发布的资产，放 `output/media/` 已经足够。
4. **规则要简单才被执行**。现在 6 个子目录反而让人放弃，2 个目录更容易坚持。

---

## 六、执行建议

1. **规则写入 AGENTS.md，明确 docs/ 的位置**
2. **temp/ 清理机制要写清楚**：建议在每日记忆规范里加一句"会话结束时手动清理 temp/"
3. **旧文件迁移**：一次性把散落的文件归位，之后坚持新规则
