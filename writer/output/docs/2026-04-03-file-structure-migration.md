# 文件目录规范迁移工作总结

**日期：** 2026-04-03  
**参与人：** 金哥 + 5人团队  
**状态：** ✅ 已完成

## 1. 今天做了什么（背景）

今天凌晨，团队6人（包括金哥）围在一起，用一次深度讨论统一了所有人的文件目录规范。起因是各人工作区结构各异，找文件靠"我记得存在那儿"，协作时经常互相找不到资源。**这次讨论解决了一个核心问题：团队文件该往哪放。**

---

## 2. 最终确定的目录规范（完整结构）

```
{workspace}/
├── output/          ← 生成物（永久保留）
│   ├── docs/        ← 文本文档（分析报告、方案、会议记录、调研等）
│   ├── data/        ← 结构化数据（JSON、CSV、Excel等）
│   ├── media/       ← 视觉素材（图片、视频、漫画、表情包）
│   └── reports/     ← 正式交付报告（定稿版报告、PPT等）
├── data/             ← 运行时系统数据（心跳状态、skill调用记录等）
├── memory/           ← 每日记忆
├── temp/            ← 临时文件
│   └── wip/         ← 工作中临时脚本
└── *.md             ← 核心配置文件（AGENTS/SOUL/IDENTITY/USER等）
```

**核心规则：** 生成物进 `output/`，临时物进 `temp/`，系统数据进 `data/`，配置文件放根目录。

---

## 3. 决策过程中最重要的两条原则

**原则一：临时判断——用完即弃进 temp/，以后可能查阅进 output/**

面对新文件，先问自己"用户以后可能回头查阅吗？"否→temp/；是→output/。这是最简单的判断标准，减少了一半的纠结。

**原则二：output/ 子目录按内容类型划分，不按来源划分**

`docs/` 放文字，`data/` 放数据，`media/` 放视觉素材，`reports/` 放正式报告。**类型即分类维度**，避免了"这个文件是谁生成的"这种模糊问题。

---

## 4. 印象最深的收获

讨论中我们发现，很多人习惯按"来源"分类（谁的、哪来的），但更清晰的逻辑是按"用途"分类（干什么用）。**一旦切换到用途思维，目录归属几乎不需要争论。** 这次迁移让团队从"文件乱放"走向了"有共识的秩序"。
