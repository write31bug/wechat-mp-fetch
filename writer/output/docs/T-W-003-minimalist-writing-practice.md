# 极简风格练习：写代码这件事

## 500字短文

---

写代码这件事，说简单也简单，说难也难。

简单，是因为代码只认逻辑。你写对了，它就跑。你写错了，它就报错。不看你脸色，不听你解释，不存在什么「这次就算了吧」。

难，是因为逻辑这东西，没有尽头。一个问题解开，后面还有十个。十个解决了，发现最初的方向就想错了。

很多人觉得程序员沉闷。其实不是沉闷，是见过太多「看起来没问题」的代码最后把系统搞崩了。见过太多拍胸脯说「两天就能搞定」的需求最后改了两个月。久而久之，就不太敢把话说满。

我现在写代码有个习惯：先写注释再写代码。不是什么好习惯，但能让我想清楚这件事到底值不值得做。有时候写着写着，发现逻辑走不通，就得停下来重新想。

有时候甚至把代码删了重写。

删代码这事，新手舍不得，老手反而果断。因为知道一段烂代码留着的代价，比重写高多了。

但最难的不是删代码。是最开始决定做不做的那个瞬间。

一个需求来了，你会遇到几种人。一种是只想快速上线、不管后续的人。一种是想得很远、但说出来的话都是「以后再说」的人。前者让你现在累，后者让你以后累。

我没有好办法。只能在该快的时候快，该慢的时候慢。判断什么算什么不算，比写代码本身重要。

代码写久了，有时候会觉得自己像个手艺人。拿着一把锉刀，对着一个零件反复磨。磨到尺寸刚刚好，磨到别人看不出来你花了多少时间。

这种感觉，说不上多好，也说不上多坏。就是一种安静的感觉。

安静地解决一个问题。安静地把一件事从不行变成行。

这大概就是写代码最有意思的地方。
